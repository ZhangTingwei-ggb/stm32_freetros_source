# LCD 驱动详解（`Core/BSP/lcd.h` + `lcd.c`）

这份文档对应**简化后**的驱动。整个驱动只有三个对外函数：

```c
void LCD_Init( void );                                              /* 开机初始化 */
void LCD_Clear( uint16_t color );                                   /* 整屏刷一个颜色 */
void LCD_ShowString( uint16_t x, uint16_t y, const char *str, uint16_t color );
```

没有画框、没有分隔线、没有放大字体。需要那些效果时，用上面三个函数自己拼。
**代码越短，需要理解的东西越少** —— 这是这一版重写的唯一目的。

---

## 0. 先建立三个概念

1. **这块屏不会"读"，只会"写"。** 单片机把颜色一个像素一个像素推过去，屏自己记在显存里。
2. **颜色就是一个 16 位数**（RGB565）。写 `0x0000` 就是黑，写 `0xFFFF` 就是白。
3. **坐标是"第几列第几行"**，左上角是 (0,0)，右下角是 (239,319)。

所以"在屏上显示信息"这件事，本质就是：**往指定坐标连续写一堆 16 位数**。
剩下的全部细节，都是"怎么把这一堆数送到正确的地址上去"。

---

## 1. 硬件连接：为什么"写个内存地址"就能控制屏幕

屏的数据线接在 STM32 的 **FSMC**（外部存储器控制器）上。FSMC 本来是接 SRAM 的，
它会把某个地址范围映射成"对外的读写操作"。屏挂在 **Bank1 的 sector4**，基址 `0x6C000000`。

屏上有两根关键信号：

| 信号 | 接到 | 作用 |
|---|---|---|
| CS | FSMC_NE4（PG12） | 片选，选中这块屏 |
| RS | FSMC_A10（PG0） | **0 = 接下来是命令，1 = 接下来是数据** |

### 那个 `0x7FE` 是怎么来的

RS 接在地址线 A10 上，所以**你访问的地址的第 10 位决定了写的是命令还是数据**。
但 FSMC 工作在 16 位总线模式，内部地址总线会右移一位：

```
HADDR[25:1] -> FSMC_A[24:0]
```

所以 `FSMC_A10` 对应的是 **HADDR 的第 11 位**，也就是字节偏移 `1 << 11 = 0x800`。

代码里用结构体把两个"寄存器"放在一起：

```c
typedef struct
{
    __IO uint16_t LCD_REG;      /* 偏移 0 -> 写命令 */
    __IO uint16_t LCD_RAM;      /* 偏移 2 -> 写数据 */
} LCD_TypeDef;

#define LCD_BASE    ( ( uint32_t ) ( 0x6C000000UL | 0x000007FEUL ) )
#define LCD         ( ( LCD_TypeDef * ) LCD_BASE )
```

要让 `LCD_RAM` 落在 bit11 = 1 的位置上，结构体基址必须是 `0x800 - 2 = 0x7FE`：

```
&LCD->LCD_REG = 0x6C000000 | 0x7FE + 0 -> bit11 = 0 -> 命令
&LCD->LCD_RAM = 0x6C000000 | 0x7FE + 2 -> bit11 = 1 -> 数据
```

于是"往屏幕写命令"就变成了 `LCD->LCD_REG = 0x2A;` —— 看起来像赋值，
实际是在总线上产生了一次带正确 RS 电平的写操作。

## 2. `lcd.h` 里的三组设置

### 2.1 方向与尺寸

```c
#define LCD_MADCTL      0xA8U
#define LCD_W           240
#define LCD_H           320
```

`0x36`（MADCTL）决定显存怎么映射到玻璃上：bit7 MY 行序、bit6 MX 列序、
bit5 MV 行列交换、bit3 BGR 红蓝交换（本屏必须为 1）。

**⚠️ 这块屏的 MV 位和 ILI9341 手册是相反的 —— 以实测为准，别照手册推：**

| MADCTL | 实测结果 |
|---|---|
| `0xA8` | 240 x 320，正立 ← **用这个** |
| `0x68` | 240 x 320，上下颠倒 |
| `0xC8` | 320 x 240 |
| `0x08` | 320 x 240，上下颠倒 |

按手册，MV=1 应该得到 320x240；实测却是 240x320。
所以 `LCD_W` / `LCD_H` 是**按实测写死的**（换到 `0xC8`/`0x08` 那一组时要把两个值对调）。

结论怎么来的：用户先后报告 `0x68` 是竖屏（只是上下反）、`0xA8` 是竖屏正立、
`0xC8` 是横屏 —— 按手册模型这三个全错，按上表全对。**方向问题一律以用户实测为准。**

### 2.2 颜色极性（反色）

```c
#define LCD_INVERSION_OFF   0x20U   /* 正常显示 */
#define LCD_INVERSION_ON    0x21U   /* 每个像素取反 */
#define LCD_INVERSION       LCD_INVERSION_ON
```

有些模块用的是**常白（normally white）面板**：控制器默认把 `0x0000` 显示成**白色**。
这时整个主题会反相 —— 暗色主题变成"白底黑字"，`LCD_COLOR_BG` 刷出来是一片白。

**判定方法：整屏刷 `0x0000`。**

| 现象 | 说明 | 该发 |
|---|---|---|
| 出来是**白**的 | 面板把 0 显示成白 = 反相了 | `0x21`（ON） |
| 出来是**黑**的 | 颜色本来就对 | `0x20`（OFF） |

本板实测是白的，且初始化里原本**没有任何**反相命令，所以定稿 `LCD_INVERSION_ON`。

**这个坑为什么难发现**：反相后的画面是"白底 + 深色字 + 浅色标题栏"，
看上去像一个**完全正常**的浅色 UI，不会让人怀疑是故障。
只有专门做了暗色主题、期待黑底却看到一片白，问题才暴露出来。

### 2.3 颜色 RGB565

每像素 2 字节：**红 5 位 + 绿 6 位 + 蓝 5 位**（绿色多一位，因为人眼对绿色最敏感）。

```
r5 = round( R * 31 / 255 )
g6 = round( G * 63 / 255 )
b5 = round( B * 31 / 255 )
value = ( r5 << 11 ) | ( g6 << 5 ) | b5
```

每个宏旁边都写了源码色，方便重新调色：

| 宏 | RGB565 | 源码色 | 用途 |
|---|---|---|---|
| `LCD_COLOR_BG` | `0x0000` | `#000000` | 底色（也是所有文字的背景色） |
| `LCD_COLOR_TEXT` | `0xE77E` | `#E6EDF3` | 标题、正文 |
| `LCD_COLOR_LABEL` | `0x8CB3` | `#8B949E` | 小标题、次要文字 |
| `LCD_COLOR_TEMP` | `0xFD8A` | `#FFB454` | 温度读数（暖橙） |
| `LCD_COLOR_HUMI` | `0x5F38` | `#5EE6C4` | 湿度读数（冷青） |
| `LCD_COLOR_OK` | `0x6E6F` | `#6FCF7F` | 状态正常 |
| `LCD_COLOR_WARN` | `0xE588` | `#E3B341` | 状态等待 |
| `LCD_COLOR_ERR` | `0xEB8E` | `#F07070` | 状态出错 / 读数无效 |

**建议用脚本算，不要手算** —— 移位容易错位，而且错了要等烧到板子上才发现。

### 2.4 背光

PB0 高电平点亮。**"屏亮但全白"和"屏完全不亮"是两个不同的问题**：
不亮说明背光没开或排线没插好；亮但没图像说明初始化或 FSMC 有问题。

## 3. `lcd.c` 逐个函数

### 3.1 两个最底层的函数

```c
static void LCD_WriteCmd( uint16_t cmd )   { LCD->LCD_REG = cmd;  }
static void LCD_WriteData( uint16_t data ) { LCD->LCD_RAM = data; }
```

整个硬件接口就这两行。后面所有功能都是它俩的组合。

### 3.2 `LCD_SetWindow()` —— 最重要的一个

```c
static void LCD_SetWindow( uint16_t x0, uint16_t y0, uint16_t x1, uint16_t y1 );
```

屏内部有个**地址计数器**，记录"下一个像素写到哪"。
`LCD_SetWindow` 干三件事：

1. `0x2A` 设定列范围（x0 ~ x1）
2. `0x2B` 设定行范围（y0 ~ y1）
3. `0x2C` 告诉屏："从现在开始，每次写数据都是一个像素"

之后连续写 `(x1-x0+1) * (y1-y0+1)` 个颜色值，屏会自己按行推进，**不用再发坐标**。
写满整个矩形后计数器回到起点。

**⚠️ 这就是"越界会变成乱码"的原因**：如果写的像素比窗口多，计数器会**回绕到左边继续画**，
于是屏幕上出现的是错位的碎块，而不是被裁掉 —— 很难反查。

### 3.3 `ILI9341_Init()` —— 上电配置序列

一长串 `命令 + 参数`，绝大多数是芯片厂给的魔数，**日常不需要理解**。只有三个必须知道：

| 命令 | 值 | 说明 |
|---|---|---|
| `0x36` MADCTL | `LCD_MADCTL` | 方向 + RGB/BGR 顺序 |
| `0x3A` COLMOD | `0x55` | 16 位/像素（RGB565），必须和 FSMC 总线一致 |
| `0x20`/`0x21` | `LCD_INVERSION` | 面板颜色极性 |

另外两处时序：`0x01`（软复位）后等 120ms；`0x11`（退出睡眠）后等 120ms
（等电荷泵升压，省掉会白屏）。

**这段不要随便删**。它是从 ILI9341 手册的官方初始化序列抄来的，
gamma / 电源 / VCOM 那些值决定了颜色好不好看，删掉不会立刻报错，但画面会变差。

### 3.4 `LCD_Init()`

```c
void LCD_Init( void )
{
    ILI9341_Init();
    HAL_GPIO_WritePin( LCD_BL_GPIO_Port, LCD_BL_Pin, GPIO_PIN_SET );  /* 开背光 */
    LCD_Clear( LCD_COLOR_BG );
}
```

注意顺序：**`MX_FSMC_Init()` 必须先跑过**，否则 FSMC 还没配置，
所有总线访问都是空操作，屏幕不会有任何反应。

### 3.5 `LCD_Clear()`

```c
void LCD_Clear( uint16_t color )
{
    LCD_SetWindow( 0, 0, LCD_W - 1, LCD_H - 1 );
    for( uint32_t i = 0; i < ( uint32_t ) LCD_W * LCD_H; i++ )
        LCD_WriteData( color );
}
```

打开整个屏幕的窗口，然后写 240×320 = 76800 个同样的颜色。

### 3.6 `LCD_ShowChar()` —— 一个字符怎么变成像素

字模存在 `lcdfont.h` 里：每个字符 **24 行，每行 2 字节 = 16 位，最高位是最左边的像素**。

```c
uint16_t bits = ( ( uint16_t ) p[ row * 2 ] << 8 ) | p[ row * 2 + 1 ];
```

把两字节拼成一个 16 位数，然后**从最高位开始逐位判断**：

```c
LCD_WriteData( ( bits & ( 0x8000U >> col ) ) ? color : LCD_COLOR_BG );
```

- 该位是 1 → 写前景色（笔画的"墨"）
- 该位是 0 → 写 `LCD_COLOR_BG`（背景）

所以每个字符都要写满 16×24 = 384 个像素，**背景也是真的写进去的**。
好处是：**文字会自己覆盖掉底下的旧内容**，不用先擦再画。

### 3.7 `LCD_ShowString()`

```c
while( *str )
{
    LCD_ShowChar( x, y, *str, color );
    x += FONT_W;        /* 每个字符占 16 像素宽 */
    str++;
}
```

就是一个循环，每画完一个字符把 x 往右挪 16 像素。
**不做自动换行** —— 需要换行就自己调两次 `LCD_ShowString()` 传不同的 y。
（少一个功能，少一段要读的代码。）

## 4. 调用层次

```
LCD_Init()                     LCD_Clear()              LCD_ShowString()
   |                              |                          |
   +-- ILI9341_Init()             |                          +-- LCD_ShowChar()
   |      +-- LCD_WriteCmd()      |                          |      |
   |      +-- LCD_WriteData()     |                          |      +-- LCD_SetWindow()
   +-- 开背光                      |                          |      +-- LCD_WriteData() x384
   +-- LCD_Clear()  ---------------+                          |
                                       +-- LCD_SetWindow()     |
                                       +-- LCD_WriteData() x76800
```

三个对外函数最终都落到 `LCD_WriteData()` 这一个动作上。

## 5. 常见故障速查

| 现象 | 原因 |
|---|---|
| 全黑，连背光都没有 | 背光没开（PB0）、排线没插好、板子没复位 |
| 屏亮但全白 | 初始化没跑完（检查 `MX_FSMC_Init()` 是否在 `LCD_Init()` 之前）、或面板极性反了（见 2.2） |
| 颜色全反：暗色主题变白底黑字 | 面板是常白型，`LCD_INVERSION` 应为 `LCD_INVERSION_ON`（见 2.2） |
| 红蓝颠倒 | MADCTL 的 BGR 位（bit3）不对 |
| 画面方向不对 / 上下颠倒 | 改 `LCD_MADCTL`（见 2.1 的实测表） |
| 只显示一部分 | `LCD_W` / `LCD_H` 和 MADCTL 不匹配，或坐标超出屏幕 |
| **右边或底部出现乱码碎块** | **某个字符串超出了 `LCD_W`**，地址计数器回绕到左边了。见第 6 节 |
| 花屏 / 随机噪点 | FSMC 时序（`Timing.DataSetupTime` 等）太紧，或排线接触不良 |

## 6. 改界面前必须做的事：算宽度

字体是 16×24，所以 **240 像素宽一行只能放 15 个字符**。
一个字符串超出右边界的后果**不是被截断，而是回绕到左边变成乱码**，非常难查。

两条规则：

```
横向： x + len(str) * 16 - 1  <  LCD_W
纵向： y + 24 - 1             <  LCD_H
```

### 三个坑

1. **不要用眼睛数字符。** `"Status: WAIT  "` 看着像 12 个字符，其实是 14 个。
   用脚本 `len()` 数 —— 这个项目里已经因此错过两次。
2. **`"%2d"` / `"%-4lu"` 里的数字是"最小宽度"，不是"最大宽度"。**
   `"ERR:%-4lu"` 在计数器涨到 10000 时会变成 9 个字符，字符串悄悄变长。
   要么按最大位数算，要么在格式化时就 clamp 住：
   ```c
   snprintf( buf, sizeof( buf ), "ERR:%-4lu", ( errCnt > 9999UL ) ? 9999UL : errCnt );
   ```
3. **重新绘制时字符串不能变短**，否则旧内容会残留。
   本工程的做法是让每种状态的字符串**等宽**：
   `"Status: WAIT"` / `"Status: OK  "` / `"Status: ERR "` 都是 12 个字符。

### 用工具查，别手算

```bash
python ~/.workbuddy-ai/skills/lcd-ui-audit/audit.py Core/Src/main.c
```

它会自己从 `lcd.h` 推出画布尺寸、展开所有 `snprintf` 格式串、逐行给结论
（`OK` / `TIGHT` / `OVER`），有越界时退出码为 1。**改完布局就跑一遍。**

## 7. 想加功能时怎么加

这一版刻意砍掉了两个功能，需要时可以按下面思路加回来（都不复杂）：

- **更大的字**：在 `LCD_ShowChar()` 里把"写 1 个像素"改成"写 scale × scale 个像素"，
  再让行重复 scale 次。这就是最近邻放大，数字和字母看起来还不错。
- **色块 / 分隔线**：写一个 `LCD_Fill(x0, y0, x1, y1, color)`，
  内部就是 `LCD_SetWindow()` + 一个写 `(x1-x0+1)*(y1-y0+1)` 次的循环，
  和 `LCD_Clear()` 一模一样，只是窗口不是整屏。

**加之前先想清楚是否真的需要** —— 每加一个函数，就多一段以后要读懂、要维护的代码。
